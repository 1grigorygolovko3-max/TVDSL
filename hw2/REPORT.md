# Отчёт HW2

Ветка: **LL(1), рекурсивный спуск** (`parser.Parser`). Генератор не используется.
Лексер HW1 подключён как есть: НКА Томпсона → ДКА подмножеств → Хопкрофт.
`Lexer.scan` отдаёт токены с позицией `строка:столбец` (с 1). `WS` и `COMMENT` в поток не попадают, но позицию сдвигают.

## Грамматика

Финальный вид и отклонения от приложения В — в [grammar.txt](grammar.txt).
Кратко: `requires` стоит **до** `returns`; тела `if`/`while` только блоки; `->` правоассоциативна, `or`/`and` и `+` `-` `*` `/` левоассоциативны, унарный `-` правый и теснее умножения.
`a[i] = v` в AST уже лежит как `a = set(a, i, v)`.

## AST

Текстовое дерево, отступ два пробела, классы пакета `ast`. Корень `Module`.
Пустые `requires`/`ensures` и пустой `uses` в текст не печатаются.
Ошибки — строки `error строка:столбец: сообщение`, код возврата 1.

## Ошибки

Режим паники. В операторе синхронизация по `;` или `}`. В функции — по закрывающей скобке тела, со счётчиком вложенности. На каждом сбое вход сдвигается хотя бы на токен, число сообщений ограничено 40, поэтому разбор заканчивается.
Пустой файл — `1:1: пустой ввод`. Файл только из пробелов и комментариев даёт ту же ошибку на позиции конца файла.
Символ вне ASCII — лексическая ошибка с его позицией.

## Лексер (HW1, без изменения автомата)

Размеры на этом наборе токенов: **130** состояний до минимизации, **120** после. Ловушка — состояние `ERROR` с петлёй по ASCII `0..127`. В JSON рёбра ловушки опущены: есть `"trap"` и `"unlistedGoesToTrap": true`. `00` режется на два `INT`, целиком это не число.
